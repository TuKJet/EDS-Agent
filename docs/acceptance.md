## 三条真实任务

`examples/acceptance/cad.json`、`cae.json`、`coupled.json` 提供可执行任务草案、
参考关系、所需观察、数值容差和实验预算候选。取得 VM/MCP 后先完成 M0：确认实际工具能表达这些任务，
或使用用户已有资产替换问题族；在运行前冻结阈值、计算时间、模型/宿主/软件版本、参考来源和资料快照。
不能用实跑结果反过来放宽通过阈值。

CAD 任务不启用 CAE；CAE 从分析对象出发不依赖 CAD 编辑；联合任务至少完成一次跨域反馈，
再展示一项有依据的单端局部修改。隐藏变更不得在方法中预列具体候选，观察 Codex 自主生成/组合方案。

每个任务均保留：

- 输入工程和版本、目标与阈值、工作区、可用资源和预算。
- 实际加载的 Skill/方法版本、候选区别、实验意图、预期判别观察。
- 工具调用输入、后端 task_id、原始状态历史、实际模型回读及与提议差异。
- 原始输出、数值质量、独立参考、评估、研究方向变化和停止理由。
- 人工输入次数、实验/运行次数、耗时和可获得的模型成本；未获得数据记为缺失。

AC-07 用真实持久任务结束会话后新会话恢复；AC-10 加入人工修改；AC-14 加入实际表达偏离；
AC-15 覆盖四种提取选择；AC-16/17 使用真实来源的完整单元及数据库删除重建；
AC-18 同时展示有效采用和条件不符时限制/拒绝。原始结果保留，不将模拟结果替换为“真实通过”。

## 验收记录格式

每项 AC 使用一条 JSON 或 Markdown 记录，包含 `case_id`、`status`（not_run/passed/failed/blocked/skipped_by_user）、
`environment`、`input_versions`、`budget`、`evidence_refs`、`observations`、`limitations`、`next_action`。
passed 必须有真实执行证据；缺 VM/MCP 的项目为 not_run，不记成产品能力失败。用户明确要求跳过时记录 `skipped_by_user`、原话及适用项目，不计入通过，也不以模拟操作替代该项真实验收。
M1～M4 是否完成按原 `doc/EDS-Agent_Development_and_Acceptance.md` 的退出条件判断。

## 学术评测

B0 参数优化、B1 Codex+同工具、B2 增加领域方法、B3 增加显式状态与证据；
保持模型、任务、工具、参考数据及预算一致并记录差异。知识消融固定同一资料快照，分别比较宿主文件搜索、
单元关系+SQLite 检索，以及启用/停用经验的效果。预先隔离未见工况和未来反馈，不将测试答案提前入库。
重复次数、时间预算和评价量在实际问题族确定后固定。当前没有对照结果，不提出论文新颖性或效率提升主张。
