# 实施边界与验证计划

日期：2026-11-02。依据 `doc/` v0.2 与本次用户开发指令。

需求文档中的“本轮只写文档”属于上一轮阶段限制，本次开发指令已替代。
第一宿主确定为未修改源码的 Codex；其负责推理、方案生成、资料读取、
实验选择、工具调用、结果解释和经验抽取。项目不调用模型 API，不自建 Agent 循环。

## 开发交付

1. `eds/study.py`：版本化工程对象、实验和执行、证据与评估、接续与变更影响。
2. `eds/knowledge.py`：显式登记的完整 Markdown 单元、SQLite/FTS/ngram 派生索引、来源回读与重建。
3. `skills/`：工程、CAD、CAE、联合方法，由 Codex 原生加载。
4. `eds/backends.py`：用户后端能力描述及本地语义检查；执行通过 Codex 已连接 MCP。
5. CLI、安装工具、可运行离线样例、验收任务与需求映射。

全部采用 Python 3.11+ 标准库；不引入第三方运行依赖。生产工程及知识数据放独立工作区。
模块边界独立并行开发，最终由主代理集成并执行完整离线测试和独立审查。

## 验证顺序

先验证记录约束、任务中断与未知状态、版本关系、手动变更、完整单元召回、
索引损坏和重建，再运行三条路径的离线接口演示和 CLI 安装检查。
离线工具夹具只检验记录和接口，不作为真实 CAD/CAE 操作成功的证据。

实际 M0 资源盘点仍需用户提供 VM、MCP 能力、可用工程/参考和预算。
本地开发完成后收集这些信息，固定真实任务阈值，再开展 AC-01～AC-18 全流程验收。
M1～M4 的真实闭环/发布与学术效果不能仅由离线测试宣告通过。
