# Codex Skills 离线前向检查

日期：2026-11-02。由独立验证代理读取技能与方法，处理一个先前未提供给技能编写者的请求。
范围是方法行为检查，无真实 MCP、资产或求解结果。

## 输入

CAE 任务上轮提交时聊天中断，记录为 submitting 且缺 task_id。用户把厚度从 10 mm 改为
12 mm，旧分析仍为 10 mm。当前长度 20 mm；历史经验仅支持细长、小挠度梁。

## 观察到的判断

- 保留 10 mm 原输入版本，将 12 mm 变化单独记录；旧结果不能直接用于新版本。
- 缺少 task_id 时先寻求后端任务清单/幂等键等查询能力，无法查询则明确缺口，不能盲目重复提交。
- L/h 约 1.67，不满足历史细长梁经验的适用条件。将经验限制为自检或拒绝作为预测依据。
- 形成包含剪切影响的建模比较，记录候选假设、预期差异和判别观察；没有实际观测时不填造结果。
- 区分数值收敛、理想化解析自检和真实物理依据；缺材料、载荷、边界与独立参考的信息保持缺失。
- CAE 路径无需补造可编辑 CAD 工程，也不要求用户先批准普通研究步骤。

## 结论与修正

该模拟请求展示了方法对中断、模型差异和历史适用性冲突的处理。
它不能证明真实任务中的自主方案质量、工具调用正确性或物理预测有效性。

独立检查同时发现绑定 JSON 对非有限值的接收缺口，已经改为严格解析并加入回归测试。
安装器保留仓库范围检查，并明确拒绝链接/重解析路径；四个 Skills 已安装到本工程，
安装副本与源文件一致性由 `python -m eds install-skills --check` 检查。
完整原始离线检查记录位于开发工作区 `.test-tmp/forward-review/README.md`，其中测试数量属于早期快照；
最终测试结果以 [本地验证报告](validation-report.md) 为准。

## 接续摘要补充检查（2026-11-02）

后续源码检查发现，原来的 `resume()` 会返回当前对象完整 payload 和未结束 Run 的
输入快照、历史及原始输出。仅靠 Skill 的按需读取要求，仍不能避免这些内容进入主上下文。
现将默认接续输出改为研究摘要、固定版本引用与任务状态索引；指定 `show --ref` 或
`show --run` 才读取对应记录，`resume --full` 保留原详细视图。Skill 已明确不把详细视图
作为启动读取动作。此处是确定性字段投影，不会自动生成或替代工程判断。

新增回归验证嵌套原始输出不会进入摘要，unknown/submitting 和原输入版本不会丢失，
失败 Run 仍可定位，详细记录可完整取回，读取不会改动保存文件；空 Run ID 不会退化为
全量读取，原有 `show --ref ... --kind ...` 组合保持可用。全量 97/97 通过，编译检查通过。

对已有 `workspaces/live-cad-repair/study.json` 做只读投影，统一 JSON 序列化后由
12,830 UTF-8 字节变为 6,865 字节；15 个当前对象引用、6 个失败 Run 的定位信息和查询队列
均保留，原文件 SHA-256 未变。证据见
[接续检查](../workspaces/progressive-disclosure/resume-check-20261102.json)和
[测试日志](../workspaces/progressive-disclosure/test-results-20261102.txt)。
该样本没有未结束 Run；unknown/submitting 的保留由回归测试覆盖。字节数不等于 token
消耗，也不证明思考质量提高或实机全流程验收通过。
