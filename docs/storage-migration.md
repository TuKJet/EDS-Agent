# 从完整快照迁移到实验摘要账本

迁移改变存储表示，不创建新的科学结果版本。实验实体、固定引用、Run 身份和状态历史、关键参数、
数值、判断与限制保持原义。中央经验中的完整 Run 输入、输出和历史不再重复存储；Study 中必要的
大结果保存一份内容寻址文件，账本只引用它。

`eds.storage_migration.migrate_storage(study_root, knowledge_root)` 默认只预览，不修改来源文件。
报告列出需要转换的中央记录、会移除的发布快照、预计体积和需要保留的未发布旧记录。
传入 `apply=True` 才执行迁移。`backup_path` 可指定回滚包；它必须位于 Study 和知识库目录之外。

CLI 同样默认预览；执行时加 `--apply`：

```sh
python -m eds study /path/to/study storage-compact --knowledge-root /path/to/knowledge
python -m eds study /path/to/study storage-compact --knowledge-root /path/to/knowledge --apply --backup /path/to/storage-before.tar.gz
```

实际执行顺序：

1. 读取并验证 Study 与属于该 Study 的中央经验；核对转换前后的条件、证据、方法评价、判断和 Run 时间状态。
   将剥离的中央/outbox Run 输入、每次历史观察和输出，必须按逻辑内容哈希在保留的 Study Run 中找到。
   历史记录允许是按日期截取的观察子序列；若某项数据仅在待剥离快照中存在，迁移明确拒绝，不丢弃或另存全量快照。
2. 把将要改写的 Study、中央 JSON/Markdown 保存为一个压缩回滚包，并重新读取验证每个成员的哈希。
3. 生成精简记录和必要的单份结果文件，写入包含所有来源旧/新哈希的迁移报告。
4. 原子替换来源文件，重建知识索引，重新读取并核验 Study。图谱投影应随后通过原有同步命令重建。

历史 publication 的重复身份、拒绝和失败保留；迁移不会把一次同版本异内容拒绝改成成功。
已存在科学内容一致的中央固定版本时，outbox 中的完整记录副本可以删除。同身份但科学内容不同的拒绝尝试，
以及尚未发布且无法从中央库取得的旧记录，
只转换成精简语义记录后保留，避免丢失未完成的发布意图。新发布队列不再创建这些完整快照。

迁移报告位于回滚包旁的 `<backup>.report.json`，包含来源哈希变化和科学字段一致性结果。
还记录每个旧 publication/event 身份和旧记录哈希到中央身份的对应关系。所有 Run 的输入、输出、
状态观察和其他元数据按逻辑内容哈希核验；新单份结果文件另外核验真实字节数和哈希。
这是一次明确的表示格式变化；旧哈希不能被假称为新内容的哈希。必要原始 CAE/CAD 模型、求解输出
及外部证据不在删除范围内。

普通异常会自动恢复旧来源文件。若进程突然中断，可调用
`rollback_storage_migration(backup_path)` 恢复，再使用新的回滚包路径重试。显式回滚会验证压缩包，
并拒绝覆盖迁移完成后发生的其他修改。已完成的迁移重复执行不会再改写同一批记录。
恢复只覆盖压缩包中列明的来源，生成过的内容寻址结果文件会保留；不会把可能已被引用的证据文件自动删除。
若索引重建失败，报告单独列出 `index_restore_error`；来源仍恢复为迁移前字节，索引可再重建。
迁移不改写或回滚 registry；重建索引使用当前注册表，期间其他正常注册的新知识不会被回滚覆盖。

回滚包和迁移报告仅用于本次迁移验证。实际研究记录、检索和图谱验收后，默认清理临时压缩包和
迁移报告；仅在用户要求保留或仍需恢复时例外。删除这些临时文件不需要再生成一份永久清理报告，
也不应把全量快照换目录长期保存。正常实验记录和发布不会触发这套迁移流程。
