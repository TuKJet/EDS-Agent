# 执行 submodule 的本地补丁

本目录保存 EDS 所需的代码差异，完整执行实现继续来自 `execution-skills/` submodule。
主工程 gitlink 固定上游可下载的基础提交；适配补丁无需推回上游。

当前 CAD 的五个补丁位于 `solidworks-automation-skill/`。第四份补充可选逐面几何输出和边的直线分类；第五份提供打开文档及未保存状态检查，并拒绝关闭有保存路径但仍有未保存修改、或保存状态未知的活动文档。CAE Agent Hub 当前无需代码补丁，继续使用原有固定提交；以后确有适配需要时，按同一清单格式登记。

## 安装与检查

```powershell
git submodule update --init --recursive
python scripts/install_skills.py
python scripts/install_skills.py --check
```

默认 `auto` 对已初始化的执行端应用补丁，缺少的可选端会报告跳过。指定 `--execution cad` 或 `--execution cae` 会要求对应 submodule 已初始化；`--execution none` 仅安装 EDS 方法。

安装器会检查基础 HEAD、补丁文件 SHA-256、逐步修改前后的文件 SHA-256，并在临时目录重建整个有序补丁栈。`--check` 只检查：不会写入 submodule、EDS Skill 副本或安装恢复目录。成功应用后，再次安装直接核对现状，不重复修改。执行 readiness 也复核补丁内容，不相信一个“已安装”标记。

补丁应用产生的 Git dirty 状态是预期结果。新增补丁时，安装器能识别内容完全匹配的已完成前缀（例如先前的四份补丁），再应用剩余差异；半个补丁或其他不匹配状态、额外修改、暂存修改、版本不符均会阻断。安装器不会自动 stash、reset、拉取新版本或覆盖冲突。

文档状态检查中 `needs_save: null` 表示无法确定，不能按 `false` 处理；文档枚举失败也不表示没有打开文档。第五份补丁保护的是活动文档关闭分支，不改变原有 `close_all` 行为。只释放名额时应先确认测试文档身份与未保存状态，再单独关闭；不要使用批量关闭代替。

## 清单与维护

`manifest.json` 的 `schema` 为 `eds-execution-patches/v1`，记录 submodule 路径、`base_commit` 和有序 `patches`。每个补丁登记文件名、补丁本身的原始字节 SHA-256，以及各目标文件的 `before` / `after` 哈希；新增/删除文件的一端为 `null`。

目标文件采用 `sha256-utf8-lf`：UTF-8 文本先将 CRLF 规范化为 LF，再计算 SHA-256。已有 Windows CRLF 文件应用后保留 CRLF。补丁及清单自身由 `.gitattributes` 固定 LF。当前安装器支持普通 UTF-8 文本修改、新增和删除，不支持二进制、重命名、文件模式更改、链接或新增可执行文件。

新增适配时：

1. 在独立开发 checkout 上修改、测试，导出仅包含相关文件的 Git diff。
2. 将差异加入对应目录，登记逐步前后哈希和补丁哈希；在 `eds/install.py` 注册清单。
3. 在公开基础提交的干净 checkout 上验证首次安装、重复安装及只读检查，并运行相关执行端测试。
4. 上游升级时重新审查每份补丁。已被上游包含的补丁应删除并更新清单，不能直接换基础提交后强行应用旧补丁。

同一基础提交上已分发的补丁保持不变，后续修复追加到补丁栈末尾，以便识别旧安装的完整前缀。若改写旧补丁，已有安装会按内容冲突处理，不能靠强制应用绕过。

## 冲突与恢复

预检失败时保持 checkout 原状，报告具体原因。真正写入前，原文件和事务记录保存在被 Git 忽略的 `local/execution-patches/`；写入异常时仅恢复仍与本次写入相符的文件，保留并发修改及恢复证据。

如果进程中断，锁文件会留下 PID、主机、时间及清单哈希。处理 Agent 应先确认该进程已结束，检查相应 `transaction.json` 和备份，将本次涉及的文件恢复为清单中的完整基础或完整补丁状态，再移除该安装锁并重跑检查。不得在进程仍运行时移除锁，也不得用整个仓库的 reset 处理局部冲突。

本地补丁安装不连接或部署 VM/MCP。远端应部署已校验的补丁源码，或取得本工程后运行同一安装器；仅克隆上游仓库不包含这里的补丁。远端安装应另外核对基础版本、清单哈希和实际部署文件指纹，确认运行进程加载了新代码，再验证实际 CAD/CAE 操作；本地检查通过不代表远端已同步。
